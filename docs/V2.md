# HX-ProxyGroup v2 交付说明

本文档记录 v2 迭代交付的能力、边界与使用方式。v2 在不改变 v1 架构（Go 控制面 + Mihomo 数据面 + SQLite + 静态前端）的前提下，补齐了 v1 清单中的规则流水线、管理员认证、告警与调度增强，并交付 v2 头号功能：浏览器内终端。

## 2. 规则流水线

固定阶段：`Normalize -> Enrich -> Predicate -> Score -> Bucket -> Sort -> Limit`。

- 规则通过显式注册表构造（`pipeline.DefaultRegistry()`），无反射、无动态插件。
- 每条规则输出 Trace：`hit / miss / modified / excluded / error`，包含修改前后值与排除原因；`proxygroup.ResolveMembers` 返回完整 Trace 供 UI 解释。
- 规则运行失败只影响当前节点（fail-open + error trace），不会清空数据面配置。
- 默认加权评分：`score = Σ(weight_i × normalized_i) / Σ(weight_i)`，延迟按可配置上限（默认 2000ms）线性归一化；缺失指标策略必须显式选择 `skip` / `neutral` / `zero`。
- 代理组可通过 `rule_pipeline_json` 覆盖评分权重、追加谓词、配置分桶与每桶/总量上限；派生规则与存量 `source_spec` 行为完全兼容。

## 3. 管理员认证

- 单管理员模型。首次启动在数据目录生成 0600 权限的一次性 `admin-setup-token`；`POST /api/v1/auth/setup` 携带 Token、用户名和密码（10–128 字符）完成初始化，成功后 Token 文件删除且不再生成。
- 密码使用 Argon2id（m=19 MiB, t=2, p=1，PHC 字符串格式），常数时间校验。
- Session：HttpOnly + SameSite=Strict Cookie，绝对有效期 7 天、空闲超时 24 小时；数据库只存 Token 的 SHA-256 与绑定的 CSRF Token。
- 管理员配置完成后，全部 `/api/v1/*`（认证端点与 `/health/*` 除外）强制登录；非 GET 请求必须携带 `X-CSRF-Token`。
- 登录限速：同一来源 + 用户名连续 5 次失败锁定 5 分钟。修改管理员账号或密码会使 password_version 递增，全部会话立即失效。
- 配置完成前管理 API 保持仅环回地址可达（`config.Validate` 强制），这是引导窗口的安全边界。

## 4. 告警

- 探测器：订阅连续刷新失败（≥3）、活动快照节点数为 0、代理组解析为空、Mihomo 未运行 / 应用失败。探测器独立失败不影响其他规则。
- 状态机：按 (rule, target) 去重（SQLite 部分唯一索引保证单条 firing）；新告警立即通知，冷却 6 小时后重复通知；恢复时发送一次 RESOLVED；确认后不再重复通知；已恢复记录保留 30 天。
- 状态持久化于 SQLite，进程重启不会重新轰炸。
- SMTP 通道：`none` / `starttls` / `tls` + 可选 AUTH，配置 AEAD 加密存储，API 永不回显密码；发送失败不推进通知时间，下轮评估自动重试。
- API：`GET /api/v1/alerts`、`POST /api/v1/alerts/{id}/ack`、`GET|PUT /api/v1/alerts/settings`、`POST /api/v1/alerts/settings/test`。

## 5. 订阅调度增强

- `refresh_cron`（标准 5 字段，UTC）优先于固定间隔决定下次刷新时间；表达式在创建/更新时校验。
- 失败退避带 ±20% 随机抖动；连续失败超过 8 次后不再快速重试，回落到常规调度间隔。
- 最近一次失败以结构化 JSON 持久化（稳定错误码：`timeout` / `http_status` / `network` / `parse` / `content_too_large` / `empty_content` / `internal`，脱敏消息，时间戳），成功后自动清除，经 API 以 `last_failure` 暴露。

## 6. 浏览器内终端（v2 头号功能）

### 6.1 组成

- 后端：`creack/pty` 启动本机 Shell，`coder/websocket` 桥接；生产部署通过权限受限的本机 Unix Socket 将 PTY 交给独立 root helper，控制面不实现任何终端协议，也不运行代理流量。
- 前端：xterm.js + fit addon；客户端到服务端为 JSON 控制帧（`input` / `resize`），服务端到客户端为原始二进制输出和 `mode` 控制帧。`mode` 携带服务端从 PTY 读取的 `echo` / `canonical` 状态。

### 6.2 安全模型

1. **默认启用与紧急关闭**：终端默认启用；`HX_PROXYGROUP_TERMINAL=0` 可覆盖关闭，`HX_PROXYGROUP_TERMINAL_SHELL` 可覆盖 Shell。
2. **强制认证**：WebSocket 升级前必须持有有效管理员会话和最近 15 分钟内完成的 TOTP 2FA step-up 验证；与其余 API 不同，终端不存在"管理员未配置时放行"的引导窗口。连接后每 30 秒复核数据库 Session，退出全部会话、账号/密码变更和 Session 过期会终止已连接终端。
3. **资源边界**：默认不因空闲断开；单会话无寿命上限；并发上限 2；输入帧大小限制 64 KiB。管理员 Session 失效或 WebSocket 断开仍会立即结束 PTY。
4. **审计**：会话建立与关闭均输出结构化日志（`audit=terminal`），含操作者、来源地址、Shell、关闭原因与时长，默认进入 journald。
5. **最小环境**：Shell 只继承 `HOME`、用户身份、`PATH`、区域与时区；控制面环境变量不会透传，`HISTFILE=/dev/null` 禁止持久命令历史。
6. **风险提示**：页面在连接前展示不可撤销操作警告。
7. **提权终端**：生产 systemd 安装额外运行 `hx-proxygroup-terminal.service`。它只接受 `hx-proxygroup` UID 通过权限为 `0660` 的 Unix Socket 建立的连接，在 root PTY 中运行 Shell，因此 `su` / `sudo` 可正常工作；控制面仍保持非 root sandbox。`run.sh` 本地开发不启动该 helper。

TOTP 密钥由「全局配置 -> 账号安全」生成，使用现有 `master.key` 通过 AES-GCM 加密后写入 SQLite；API 只在生成流程返回明文密钥和 `otpauth://` 地址，不写入日志。关闭 2FA 需要当前验证码，关闭后终端不会接受连接，直到重新配置并启用 2FA。

### 6.3 本地预测回显

- 普通规范模式下，仅当服务端 PTY 同时启用 `ECHO` 和 `ICANON` 时，前端立即显示普通可打印字符，并从随后到达的相同 PTY 回显中消除重复。
- 预测回显开启时，安全的可打印输入约 12ms 合并后发送，以减少弱网中的小帧数量；回车、控制键、密码输入和 raw 模式立即发送。服务端仅在 PTY 模式变化时发送 `mode` 帧。
- 待确认回显最多保留 4 KiB；输出不一致时立即清空预测状态并回退到服务端输出。
- Enter、退格、方向键、Esc 等控制输入不预测，并立即暂停后续预测，直到服务端再次明确同步 PTY 模式。密码提示、未知 PTY 状态及 vim/top 等 raw/full-screen 程序关闭预测，避免无提示密码读取或终端控制序列被错误显示。
- 该优化消除的是键入字符等待网络往返的观感；命令执行结果仍由服务器负载和网络时延决定。

### 6.4 边界

- 当前实现是"服务器本机 Shell"；生产安装以 root PTY helper 执行，跳板式 SSH 连接到第三方主机不在本迭代范围。
- 生产部署保持控制面以不可登录的专用用户运行，但启用终端等价于向完成管理员登录和 2FA 的操作者授予 root Shell 权限。

## 9. v2.1 增量（代理服务编排与检测可配置）

### 9.1 节点质量检测

- 复测间隔、单次超时、每轮批量、测试 URL 全部可在「节点 → 检测设置」中调整（`GET/PUT /api/v1/node-settings`，存储于 `system_metadata`），调度器每轮动态读取，不再固定 10 分钟。
- 数据面故障（Mihomo 未运行 / 控制 socket 拒连）不再计入节点质量历史，整轮中止并按 `dataplane_down` 上报；节点级失败细分为 `node_unreachable`（Mihomo delay 测试 503）、`timeout`、`connect_failed`、`proxy_not_found`。
- 节点列表带出最近一次检测的错误码与原始信息，前端以中文标签+悬浮详情展示。
- 编译配置新增显式 `dns` 段（阿里/腾讯 DoH + UDP 兜底），避免系统 DNS 污染导致域名型节点全量失败。

### 9.2 代理组组合（串联 / 并联）

- `SourceSpec.group_ids` 允许组引用组：写入时校验存在性、启用状态、自引用与环（错误信息给出环路径）；被引用的组禁止删除。
- 编译器把子组名并入成员并按依赖拓扑排序输出。
- 语义：`fallback` = 串联责任链（顺序即优先级，前面可用不走后面）；`url-test` / `load-balance` 系 = 并联（配合 `limit` 即 Top-K）。

### 9.3 Listener 订阅导出

- 迁移 v10：`listeners.share_token`（唯一，随机 32 hex，已有行自动回填）。
- `GET /sub/<token>`（免登录，token 即凭证）返回 base64 订阅体，`?format=uri` 返回明文 URI 列表；mixed 入口同时导出 `http://` 与 `socks5://` 两条；环回/未指定绑定地址自动替换为请求 Host；凭据 URL 转义。
- `POST /api/v1/listeners/{id}/rotate-share` 重置链接；访问日志对 `/sub/` 路径脱敏。

### 9.4 代理服务节点展开

- 主导航不再提供独立蓝图页；代理服务列表直接显示命中节点数量，并可展开查看节点名称、协议、状态、延迟和订阅来源。
- 客户端订阅在代理服务行内按 Clash/Mihomo/Clash Verge/Stash、v2rayN/v2rayNG、Shadowrocket 和 sing-box/NekoBox 分类复制。
- Vite 开发服务器代理 `/sub/` 到控制面，确保 `127.0.0.1` 本机测试不会误取 SPA HTML。
- 拖线建立 入口→组 / 组→子组 关系，fallback 边标注链序；删除连线即解除引用；布局持久化于 localStorage。
- 检查器面板可改策略（附串并联行为说明）、子组顺序、Top-K，并可快速新建组/入口。
